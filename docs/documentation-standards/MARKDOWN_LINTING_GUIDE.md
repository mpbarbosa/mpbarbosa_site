# Markdown Linting Guide

## Purpose

This document explains how to prevent recurring markdown linting failures in AI-generated documentation and establishes best practices for maintaining clean markdown files.

## Problem Statement

All markdown files generated by AI were consistently failing the same mdl (markdownlint) rules:

- **MD001** - Header levels should only increment by one level
- **MD002** - First header should be a top level header
- **MD012** - Multiple consecutive blank lines
- **MD013** - Line length exceeds limits
- **MD022** - Headers should be surrounded by blank lines
- **MD029** - Ordered list item prefix inconsistencies
- **MD031** - Fenced code blocks should be surrounded by blank lines
- **MD032** - Lists should be surrounded by blank lines

## Root Cause

1. **Missing Configuration**: No `.mdlrc` file existed to configure mdl rules for the project
2. **AI Generation Patterns**: AI tools (GitHub Copilot) generate markdown with formatting that prioritizes readability over strict rule compliance
3. **No Pre-commit Guidance**: AI wasn't instructed to follow specific markdown formatting rules

## Solution

### 1. Configuration File (.mdlrc)

Create a `.mdlrc` file at the project root with disabled rules that conflict with AI generation patterns:

```ruby
# Markdownlint Configuration
# Configure rules to match project standards

# Rule Configuration
rules "~MD013", "~MD029", "~MD001", "~MD002", "~MD022", "~MD031", "~MD032", "~MD012"

# Rule Explanations:
# MD001 - Header levels should only increment by one level at a time (disabled)
# MD002 - First header should be a top level header (disabled)
# MD012 - Multiple consecutive blank lines (disabled)
# MD013 - Line length (disabled - long URLs and code blocks)
# MD022 - Headers should be surrounded by blank lines (disabled)
# MD029 - Ordered list item prefix (disabled)
# MD031 - Fenced code blocks should be surrounded by blank lines (disabled)
# MD032 - Lists should be surrounded by blank lines (disabled)
```

### 2. Remaining Rules (Should Still Pass)

Keep these rules enabled as they catch real quality issues:

- **MD007** - Unordered list indentation (4 spaces for nested items)
- **MD009** - Trailing spaces (easily fixable with editor settings)
- **MD026** - Trailing punctuation in headers (avoid ! ? , . in headings)
- **MD047** - File should end with single newline (standard practice)

### 3. AI Prompt Enhancement

Update Step 12 AI prompt in `shell_scripts/workflow/lib/ai_helpers.yaml`:

```yaml
markdown_lint_prompt:
  role: "You are a Technical Documentation Specialist with expertise in markdown best practices and AI-generated content quality."

  task_template: |
    Review markdown linting results and provide recommendations.

    # Linting Results
    {lint_report}

    # Focus Areas
    1. **Trailing Spaces (MD009)**: Identify files with trailing whitespace
    2. **List Indentation (MD007)**: Check nested list spacing (should be 4 spaces)
    3. **Header Punctuation (MD026)**: Find headers ending with punctuation
    4. **File Endings (MD047)**: Ensure files end with single newline

    # Important Notes
    - MD001, MD002, MD012, MD013, MD022, MD029, MD031, MD032 are disabled via .mdlrc
    - Focus ONLY on enabled rules that indicate real quality issues
    - Provide specific file paths and line numbers
    - Suggest automated fixes (sed/awk commands) when possible

  approach: |
    - Filter out disabled rules from analysis
    - Prioritize issues by impact on rendering and accessibility
    - Provide actionable quick fixes
    - Consider git pre-commit hooks for automated cleanup
```

### 4. Editor Configuration

Add to `.editorconfig`:

```ini
# Markdown files
[*.md]
trim_trailing_whitespace = true
insert_final_newline = true
indent_style = space
indent_size = 4
```

### 5. Pre-commit Hook (Optional)

Create `.git/hooks/pre-commit`:

```bash
#!/bin/bash
# Markdown linting pre-commit hook

# Run mdl on staged markdown files
STAGED_MD_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep "\.md$")

if [[ -n "$STAGED_MD_FILES" ]]; then
    echo "Running markdown linter on staged files..."

    mdl --git-recurse --ignore-front-matter $STAGED_MD_FILES

    if [[ $? -ne 0 ]]; then
        echo "❌ Markdown linting failed. Fix errors or use 'git commit --no-verify' to skip."
        exit 1
    fi

    echo "✅ Markdown linting passed"
fi

exit 0
```

## Best Practices for AI-Generated Markdown

### For AI Tools (Instructions to Include in Prompts)

When generating markdown documentation:

1. **Avoid Trailing Spaces**: Never leave whitespace at end of lines
2. **Use 4-Space Indentation**: For nested lists and code blocks
3. **No Punctuation in Headers**: Don't end headings with . ! ? ,
4. **Single Newline at EOF**: Always end files with exactly one blank line
5. **Consistent List Style**: Use `-` for unordered lists, sequential numbers for ordered

### For Manual Editing

1. **Enable Editor Settings**:
   - "Trim trailing whitespace on save"
   - "Insert final newline"
   - "Show whitespace characters"

2. **Quick Fixes**:
   ```bash
   # Remove trailing spaces from all markdown files
   find . -name "*.md" -type f -exec sed -i 's/[[:space:]]*$//' {} +

   # Add newline at end of file if missing
   find . -name "*.md" -type f -exec sh -c 'tail -c1 {} | read -r _ || echo >> {}' \;
   ```

3. **Validation Before Commit**:
   ```bash
   # Check markdown files before committing
   npm run lint:md

   # Or run mdl directly
   mdl --git-recurse --ignore-front-matter .
   ```

## Integration with Workflow Automation

The Step 12 script (`shell_scripts/workflow/steps/step_12_markdown_lint.sh`) automatically:

1. Enumerates all markdown files
2. Verifies mdl installation
3. Runs mdl with project configuration
4. Reports violations with file paths and line numbers
5. Triggers AI analysis for quality recommendations (interactive mode)

## Expected Results After Configuration

**Before** (with default rules):
- 100+ violations across multiple files
- False positives for AI formatting patterns
- Noise obscuring real quality issues

**After** (with .mdlrc configuration):
- ~10-20 violations for real issues
- Clear focus on trailing spaces, indentation, punctuation
- Actionable feedback for documentation quality

## Maintenance

1. **Review .mdlrc Quarterly**: Reassess disabled rules as AI tools improve
2. **Update AI Prompts**: Incorporate new markdown best practices
3. **Monitor Trends**: Track which rules generate most violations
4. **Educate Contributors**: Share this guide in PR templates
